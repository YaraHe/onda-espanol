# v1 Design System · 语句手札

> 状态：已确认。本文件现已正式生效，是 v1 的 **Visual Design Source of Truth**，负责视觉语言、UI 表达和跨页面一致性；不改变产品行为。

## 1. 依据与使用边界

- **为什么这样设计：**[已确认的 Design Principles](../Direction%20A%20%E2%80%94%20Refined%20%26%20%20Design%20Principles.md)。
- **整体气质：**同文件中的 `Direction A — Refined`。
- **已验证的落地参考：**[句子讲解页](../design-samples/direction-a-refined.html)与[跟读／评分反馈页](../design-samples/direction-a-refined-practice.html)。提取其共同规律，不逐像素复制 HTML Demo。
- **页面、状态与交互：**[03-UI-INTERACTION.md](03-UI-INTERACTION.md)；**功能行为与能力边界：**[02-FEATURE-SPEC.md](02-FEATURE-SPEC.md)。本文件不能覆盖这些文档的业务定义。

遇到视觉取舍时，先守住已确认的 Design Principles，再沿用 `Direction A — Refined` 的整体语言，最后参考两页样例的共通做法；单个 Demo 细节不能推翻上层规则。涉及功能或交互时，仍回到各自的设计文档，不用视觉样例改写行为。

### 稳定规则与可微调细节

**Stable Design Rules：**句子居主位；用文字层级和留白组织学习动作；仅在需要辨认内容关系或结果来源时使用少量轻量 Surface；教学标注与评估结果区分；状态明确；手机单列学习路径；桌面延续同一路径。这些规则适用于所有 v1 页面。

**Implementation-level Flexible Details：**局部像素、图标画法、轻微背景质感、按钮最终尺寸、细线样式、单个状态动效等，可在前端实现和真机检查后微调。调整不得让页面变成卡片墙、Dashboard，或削弱上述稳定规则。两个样例中的 390 × 844 设备框、演示切换器、假数据和自动跳转计时不属于生产 UI 规范。

## 2. Design Philosophy

产品应让初学者觉得自己正在**有条理地研读并练习一句西语**：安静、成熟、克制，像经过编排的学习手札。视觉特色来自西语原句、教学标注和练习反馈之间的关系，而非装饰。

将六条 Design Principles 转成 UI 判断：

1. 页面开始先确定当前句子；翻译、标注与反馈都可追溯到它。
2. 每页只突出当前学习任务与下一步操作；细节遵循既定展开与导航行为。
3. 得分之后能迅速找到问题词、建议和再次练习入口。
4. 暖色标注用于**讲解如何读**；蓝色结果线索用于**本次录音评估**。不得把文字教学标注画成客观韵律分或音高曲线。v1 西语评估不提供韵律分。
5. 等待、录音、评估、保存和失败状态以明确文字与控件变化呈现。
6. 主动学习允许停下来读；“听熟”先让用户清楚设定听力任务，再以连续播放的轻节奏执行，设置不盖过当前播放句。

不采用通用 AI SaaS、数据驾驶舱、游戏化奖励或强科技感 Voice AI 的视觉语言。

## 3. Visual Hierarchy

- **Primary：**当前西语句子，以及当前页面的核心动作或内容。讲解页是原句与理解内容；跟读页是原句、示范／录音，评分后再转向可改进之处；选句页是输入的句子。
- **Secondary：**中文翻译、核心记忆点、教学标注、与当前动作直接相关的设置、逐词反馈和建议。它们的内部主次由文字大小、字重和距离决定。
- **Supporting：**页面标题、区段标签、详细语法、列表元数据、历史时间、辅助操作和状态说明。必要状态虽不占据主视觉，也必须容易发现。
- 总分可醒目，但不得让大数字压过原句、问题词与建议；三维分和语速是解释结果的辅助信息，不做 Dashboard 式数据墙。
- 用区段标签指出内容性质，避免每个字段都配一个同等显眼的小标题。页面标题帮助定位，不代替句子成为学习页的主角。

## 4. Typography System

**字体策略：**样例用 `Spectral` 呈现西语、`Noto Serif SC` 呈现中文，形成一致的衬线阅读感。将这组合作为实现起点；若实际字体加载、跨设备字形或性能不合适，只能换成气质和阅读表现相近的组合，并在手机上对照验证。不要因字体采购或加载擅自增加未确认的依赖／服务。拉丁文与中文应像同一篇手札，不用两种互不相干的标题风格。

**简明文字角色与样例参考范围（不是逐像素要求）：**

- **Sentence：**学习页原句约 28–30px，中等字重，舒展行高；允许自然换行，不强行缩小长句。逐词反馈中按既定交互再次呈现的句子可降为约 20–22px，不能形成第二个同等强的主标题。
- **Result figure：**总分约 36–40px，但其旁边要能读到“总分／保存状态”的含义。
- **Translation / prominent reading：**约 17–18px、较宽松行高；中文长句优先保持易读。
- **Body / memory / feedback：**约 14–16px，按阅读长度给足行高；建议和词级说明不压缩成微型数据标签。
- **Section / supporting label：**约 12–14px，以位置、字重和适度字距区分。样例里更小、更浅的字只作原型参考；正式页面要检验真实手机上的可读性。

常用字重以正常、中等和少量加重为主。通过字重、位置与语义色强调具体词或动作，避免把每个标题都加粗、全大写或加装饰前缀。西语重音标注可强调对应音节，但应保留完整原句的可读性。

## 5. Color System

两份样例共享同一组关系。以下是**推荐的初始语义色**；在真实设备上可为可读性微调，不新增一套页面专属调色盘。

- **Page background `#F6F2E8`：**安静的阅读底色。
- **Learning / result Surface `#F0E9DA`：**轻量背景区段，表示同一个理解动作或同一次评估结果；不表示“所有内容都要进卡片”。
- **Primary text `#221E19`、secondary text `#544C42`、readable muted text `#6B6255`：**建立文字层级。样例中的更浅灰 `#8C8375` 不宜直接用于小号关键文字；正式实现须先检查对比度。
- **Blue accent `#2B4668`：**用于可交互文字、选中线索、评分数据线索与可查看的问题词；讲解页样例也将它用于一处实心行动按钮。这是局部颜色语义，不是所有 Primary Action 的默认填充色。
- **Teaching accent `#A63A2E`：**重音、停顿、升降调等**教学提示**；录音进行中可暂时使用同一暖色作为活动状态，但评估结果不使用它表示分数好坏。
- **Rule `#DFD6C4`：**顶栏／底部操作区边界及确有并列关系的细分隔。主要区段不靠它划满横线。
- **Text on blue fill：**仅在采用蓝色实心处理时，使用与蓝色有足够对比的浅色；样例中的浅纸色可作起点。

保存成功、保存失败、权限或网络错误等状态必须有明白的文字和可采取的动作；具体状态色在实现时从现有色系中克制地选择并检查对比度。不要只凭颜色让用户猜测状态，也不要把“发音较差”自动画成教学标注的暖红色。

## 6. Spacing & Vertical Rhythm

- 手机内容左右留稳定的阅读边距；样例在 390px 视口约为 22px，可作为起点，窄屏与安全区域优先保证正文和操作空间。
- 保持三级距离：同一信息内部最紧、同一学习动作的内容之间居中、不同学习阶段之间明显更宽。样例大致体现 **约 8–12 / 18–24 / 36–40px** 的关系；这是间距层级，不要求所有页面机械复刻同一数字。
- 一个阶段按“进入点（句子或区段标签）→ 阅读／操作 → 停顿 → 下个阶段”推进。不要用均匀的 section 间距抹平学习节奏，也不要靠空白把下一步操作推得难以寻找。
- 内容区纵向滚动；L2 主操作遵循页面文档的底部操作区，L1 保持其底部导航。固定区域须为可滚动内容留足底部空间。

## 7. Surface & Divider Strategy

**Surface 是平缓的页面背景区段，不是浮起的 Card。** 当数项内容属于同一个学习动作或同一次结果，需要被一眼识别为整体时使用。例如讲解页“翻译＋核心记忆点”、跟读页“本次评分＋词级反馈＋建议”。可使用通栏或接近通栏的轻色衬底；默认无阴影、无明显边框、无夸张圆角。

原句、教学标注、示范播放、可展开语法、一般列表与辅助操作默认直接位于页面背景上。先问“若没有这个 Surface，用户会误解内容关系或来源吗？”若不会，就不用。一个页面不应因每个 section 都套容器而变成卡片墙。

**Divider 只用于确有并列或重复关系的局部**，如语法条目或历史记录项。阶段之间用较大的留白；同一阶段内的主次用文字层级；需要整体识别内容来源时才用 Surface。教学标注可用一条从属引导线、标签对齐与行距组织，不在每行之间画线。顶栏和固定操作区的边界线属于导航边界，不应复制到每个内容块。

## 8. Component Language

以下只定义跨页视觉性格；组件出现条件、文案、顺序和行为仍以 [03-UI-INTERACTION.md](03-UI-INTERACTION.md) 为准。

- **Primary Action：**指当前页面最重要的下一步操作层级，不指定固定颜色或按钮外形。通过位置、可触达性、清楚的文案及与辅助操作的视觉对比使它易于识别；不要让多个操作同时具有相同主视觉权重。讲解页“去跟读”的蓝色实心处理是该页样例的局部做法，不能推导为查询、确认、保存等操作的全站默认样式；录音／停止按第 9 节使用麦克风控件及其状态表达。
- **Secondary / Text Action：**用文字、轻微下划线或适度色彩表达可操作性，如返回、换一句、再读一次；不为每项都造胶囊按钮。禁用态和加载态仍须可辨。
- **Navigation：**L1 底部标签、L2 顶栏返回及桌面顶部导航遵循页面结构。选中项明确，其余保持安静；导航不制造独立于学习内容的视觉主舞台。
- **Section Label：**帮助用户快速定位“原句、翻译、记忆点、语法、示范、本次练习”等真实内容区。短、可读、位置稳定；不为装饰添加无意义眉题。
- **Sentence Display：**原句优先，可自然换行；标注依附原文。个人句子选择与记录列表中的句子仍是列表项的主要文字，元数据退后。
- **Pronunciation Annotation：**重音、连读、停顿、升降调用暖色与文字解释呈现；只表现已有教学数据。标注缺失时隐藏对应内容并说明“该部分未生成”，不留空轨道，不使整页看似失败。
- **Audio Demo / Playback 与 Speed Selector：**整句与选中单词的示范入口易辨，播放／停止状态清楚，不让每个单词的入口压过原句或反馈；语速选择像轻量文本控制，当前值有非颜色的选中线索。听熟的当前播放句可高亮，但播放设置不压过聆听内容。
- **Recording / Voice Interaction：**采用可辨认的麦克风形态与文字标签，初始、录音中、评估中是同一控件的状态演变。详见下一节。
- **Score Display 与 Word-level Feedback：**结果处于一个语义区段；总分、三维分、语速先提供概览，问题词沿原句标出，选中词的标准发音与点词说明就近呈现，建议随后，最后接“再读一次”。复练时突出简短目标，完整讲解按需进入。不要把低分词做成与教学重音相同的暖色标注。
- **Expand / Collapse：**语法分析以标题行、展开指示和缩进表达从属；默认收起由交互文档决定。不要为展开内容再套一张 Card。
- **Input / Form / Filter / Switch：**输入内容和当前选择应比控件外壳更显眼；错误文字靠近对应字段。听熟范围、方言选择与显示开关沿用同一克制的控件语言，不用大量胶囊填满页面。具体控件形态在首次实现时对照真机确定。

## 9. Voice / Recording Interaction

跟读样例验证了一个**有说话辨识度、但不带强科技感**的录音主操作：麦克风符号、清楚的操作文字、稳定位置，以及录音时有限的暖色强调。初始、录音中、评估中沿用同一控件轮廓；录音中显示计时与停止方式；评估中明确“正在评估”，避免被误认为故障或仍在录音。可以使用极轻的呼吸／等待动效，但文字状态始终完整。

录音控件服务于“听示范后模仿这一句”：用户参照示范和已有教学标注，主动模仿西语的语调、节奏、重音与停顿，尽可能接近自然的母语表达。原句、标注、示范与录音操作应保持清楚的视觉关联；这是一项目标明确的模仿练习，不代表 v1 会对这些韵律特征或音高给出客观评分。控件不能演变为霓虹、波形墙或语音助理视觉。评估返回后，结果先让用户找到问题词和提升方向，再自然接续再读。具体录音时长、失败恢复、评分保存与返回行为以功能／交互文档为准；HTML Demo 的模拟计时和自动评分不是实现契约。

## 10. States & Feedback

- **Loading / Assessing：**在触发它的控件或结果区就近表达“正在做什么”，防止重复提交；保留已知内容，不用整页遮罩取代学习上下文。
- **Recording：**控件形态、明确的“录音中／停止”文字和计时共同表达状态；不能只靠红色或动画。
- **Success：**讲解成功时进入正常阅读节奏；个人句子收录中的状态用短暂 Toast 呈现，失败后保留紧凑的可重试状态；评分成功先展示结果，再区分“保存中／已保存”。“已保存”是状态，不是新的奖励组件。新评分得到 100 分时可用一次短暂、克制的轻动效确认结果，不增加鼓励文案或遮挡反馈。
- **Error：**指出失败环节和现有恢复动作。个人句子收录失败时保留讲解并提示单独重试；评分失败时不展示假结果；保存失败或中断时保留已返回的分数并提供核对或重试，不要求重评；权限、音频与网络错误按页面文档显示。
- **Empty：**用现有任务引导下一步，如输入或识别一句、查看本人学习内容或开始练习；无个人句子时说明如何形成听熟内容，不以系统预置句填空。
- **恢复与降级：**刷新后恢复的任务须区分“本地待保存”和“云端已保存”，中断的录音或评分请求要明示；快照过期、无权访问及网络暂时不可用使用不同文案和操作，不把本地状态伪装成持久记录。
- **Degraded / partial content：**缺少可选 `annotation`、`memoryTip` 等时，只隐藏缺少的部分并就近说明；翻译等可用内容照常显示。没有动词的句子显示文档定义的“不适用／本句无动词”，不可画成错误态。

Toast、字段旁错误、保存状态和空态的具体位置与行为，按 [03-UI-INTERACTION.md](03-UI-INTERACTION.md) 执行；本节只统一视觉表达。

## 11. Responsive & Mobile-first

- 先在真实手机宽度确认原句、标注、中文段落和录音／播放控制可读可按。主要操作遵循页面文档规定的位置：L2 使用底部操作区，选句页“查询”位于内容区底部；同时考虑安全区域与键盘出现时的可达性。
- 内容保持单列纵向学习路径，长西语句子和中文解释允许自然换行；不可通过缩小文字、水平滚动或堆叠小卡片来塞下内容。
- 桌面端保持相同的页面任务、顺序和状态。依 [03-UI-INTERACTION.md §3.5.8](03-UI-INTERACTION.md) 以居中的阅读宽度扩展（文档上限 480px），L1 导航转顶部；不新增多栏工作台或独立桌面信息架构。
- 样例中的手机设备外框只用于展示，不应进入产品页面。

## 12. Motion, Icons & Illustration

**Motion：**仅为操作反馈和状态转换服务，例如展开、录音进行中、评估等待、评分满分的短暂确认或轻微进入。避免每个区块依次飞入、持续跳动和无用户触发的装饰动效。遵守 `prefers-reduced-motion`；关闭动效后仍要通过分数和静态形态读懂状态。满分动效不得遮挡评分结果，也不因重渲染或查看历史重复触发。样例中的入场动画与呼吸环可微调或省略，语义不随动效消失。

**Icons：**正式 UI 使用一套线条清楚、重量一致的图标语言；图标陪伴文字，不单独承担关键含义。样例和交互文档中的 🎙️、🔊、🔁、⚙️ 等 emoji 可视为原型／文字占位，不要求作为生产图标。图标库尚未确定，不因本文件自动引入新依赖。

**Illustration：**v1 不依赖插画或装饰图形来填补留白。若图形无法帮助识别句子、教学标注、播放或反馈，就不加入。

## 13. Accessibility

- 在页面背景与轻量 Surface 上分别检查文字和控件对比；以正文至少 4.5:1、较大文字与必要控件边界至少 3:1 作为实现检查目标。不能直接冻结样例中的浅灰小字。
- 键盘焦点始终可见；交互状态不只靠 hover。图标按钮有可理解的名称，展开、播放与选中状态可被辅助技术识别。
- 手机控件提供足够的可点击区域，优先达到约 44 × 44 CSS px 的触达空间；视觉图标本身可更小。录音主控件尤其要能稳定触达。
- 分数、问题词、录音、保存、错误和降级状态均配文字或形态线索，不单靠色彩。长句、系统文字放大、较窄屏幕和中西文混排不能破坏阅读顺序。
- 尊重系统减少动态效果设置；动画暂停或关闭后不丢状态信息。

## 14. 未制作视觉样例的 v1 页面如何沿用本系统

以下是**视觉应用方法**，不是新增页面行为。具体内容和状态仍按 [03-UI-INTERACTION.md](03-UI-INTERACTION.md)。

- **登录：**表单是唯一主任务；字段、错误与提交动作形成一组。无需营销 Hero 或功能卡片。
- **选句：**输入或粘贴中的西语句子为主，OCR 作为辅助；示例与首次引导帮助用户带入自己遇到的句子，不提供系统句库或随机内容。「最近练习」作为轻量回访入口；个人句子管理从听熟页进入。
- **听熟：**首先突出本次听什么、可调整的必要播放设置、句数与开始操作；「我的句子」以靠近朗读范围标题的轻量文字入口进入独立次级管理页，不能与范围选项争夺主次；具体播放列表默认收起。播放中当前句、状态与暂停／继续清楚，屏幕中文翻译与语音播放含义分开。连续聆听不需跟读页的评分视觉。
- **我的句子：**采用 L2 顶栏返回和连续轻量列表，不用重复卡片。原文是条目主信息，译文和收录时间退后；「重新学习」和「移出」保持文字操作，移出先确认并说明评分记录保留。列表多时可纵向浏览，不把管理能力塞回听熟配置区。
- **记录：**日期是分组线索，句子与最近得分构成条目；可用少量 divider 分开重复记录，不把列表变成成绩仪表盘。
- **记录详情：**原句与翻译先建立上下文；最近一次反馈及下一次复练重点高于历史明细。最近最多五次的总分曲线固定 0–100 纵轴，少量记录只显示相应点，历史明细默认收起；图线与分数均保留可读文字，不把详情做成成绩仪表盘。“再练一次／查看讲解”依既定页面主次呈现。
- **设置：**方言、分享、数据、关于按内容性质分组；保持文字清楚、控件克制，清除记录等重要操作不可被装饰掩盖。

因此，这套规则覆盖 v1 主要页面类型：表单、输入、阅读、录音／结果、个人句子选择、连续播放、历史列表与设置。尚未做视觉样例的页面可复用现有层级和组件语言，无需新增视觉方向。

## 15. Anti-patterns

- 把页面做成泛用 AI SaaS：发光、霓虹、强渐变、伪波形、模型能力标语或装饰性数据面板。
- 用相同圆角、阴影与边框包住每个 section；大量胶囊标签、浮起卡片或全页面分隔线。
- 让总分、统计或控件大过西语句子和可执行的反馈；把教学标注误画成录音的客观韵律评测。
- 为填满留白新增无价值文案、插图、动画、额外步骤或功能。
- 在桌面改成 SaaS Dashboard，或在手机靠缩小字、过窄栏位处理长句。
- 逐像素照搬 Demo 的设备框、emoji、纹理、动画、局部间距、模拟数据和状态计时。

## 16. Guidance for AI Coding Agents

开发新页面时依次执行：

1. 读取该页面在 [02-Feature Spec](02-FEATURE-SPEC.md) 与 [03-UI Interaction](03-UI-INTERACTION.md) 中的任务、内容、状态和交互；再读取本文件。必要时查看两个 HTML 样例的共同视觉规律。
2. 用一句话确定页面的**当前学习任务**，指出视觉主角和下一步主要操作；先排好内容顺序，再考虑组件外壳。Primary Action 是操作层级，不等于蓝色实心按钮；不能仅凭其名称套用固定颜色或外形。
3. 首先使用文字层级与三级留白组织内容。只有能解释内容关系或结果来源时才增加 Surface；只有同一区域存在并列／重复项时才增加 Divider。
4. 优先复用已有句子展示、标注、操作、结果与状态语言。不得为新页面自行创造一套配色、卡片造型或独立 Design Direction。
5. 对照本文件第 14 节检查无视觉样例页面；检查手机长句、空态、等待、错误、降级和主要操作的实际可见性。
6. 在真实设备与浏览器中核对可读性、对比、触达、焦点和减少动态效果。可调整实现级尺寸、图标与微动效，但不得破坏稳定规则。若需引入新依赖，遵守仓库 `AGENTS.md` 的事先确认规则。
7. 若新场景无法由现有规则覆盖，报告缺口及受影响页面；不要暗中补写新视觉规范或改变产品行为。经用户确认后再更新本文件。
