# 文档 7 · 开发计划 + 验证

> 将设计转化为可执行的开发计划：按依赖拆阶段、MVP 优先、区分前端/后端/数据库/AI/部署任务，适合个人开发者按顺序执行。

## 7.1 开发原则与阶段总览

**原则**：① 依赖优先——先地基后上层；② MVP 优先——先跑通核心闭环再补周边；③ 先文档后代码——改动先改 `docs/` 再写代码；④ 验收看用户可感知结果，不看内部实现。

| 阶段 | 名称 | 主要类型 | 依赖 | 核心产出 |
|---|---|---|---|---|
| 0 | 环境准备 | 账号/部署 | — | 各服务 key 可用 |
| 1 | 基础设施与骨架 | 前端/后端/数据库/部署 | 0 | 空壳可跑、链路连通 |
| 2 | 核心闭环 | 前端/后端/数据库/AI | 1 | 登录→讲解→跟读→评分→记录可查 跑通 |
| 3 | 周边功能 | 前端为主 | 2 | F1–F8 全部可用 |
| 4 | 产品调整、打磨与分享上线 | 前端/数据/部署 | 3 + 已确认的 Stage 4 目标规格 | 「讲透、读好、听熟」闭环可靠，可安全分享给朋友 |

> 阶段 0–3 的下列任务与验收保留为当时的历史计划和事实记录，不作为 Stage 4 新目标的验收口径。特别是阶段 2 的「问题词标红」及阶段 3 的内置句子库、旧「已学/全部/自定义」听力范围，已被现行 [功能规格](02-FEATURE-SPEC.md)、[交互规格](03-UI-INTERACTION.md)及 [Design System](DESIGN-SYSTEM.md) 中的 Stage 4 目标取代。Stage 2/3 的已完成验收事实不回写。

## 7.2 阶段详细

### 阶段 0 — 环境准备（账号与密钥）

- **目标**：开通全部外部服务、拿到密钥，扫清开发前置。
- **依赖**：无。
- **任务**：
  - 账号/部署：注册 Azure（建 Speech 资源，拿 key + region）、DeepSeek、Supabase（建项目）、Vercel、Render/Railway；绑 Mastercard 扣账卡。
  - 文档：把本文档集拆分为项目 `docs/` 下独立文件（PRD / spec / interaction / architecture / database / api / plan）。
- **阶段产出**：各服务 API key + 环境变量清单。
- **验收标准**：各服务控制台可登录；每个 key 能发起一次最小调用（如 Azure 能返回一句 TTS）。
- **设计依据**：[文档 4](04-ARCHITECTURE.md).6 部署架构、[文档 5](05-DATABASE.md).1 选型。

### 阶段 1 — 基础设施与骨架

- **目标**：搭起前后端空壳 + Supabase 数据层，打通部署链路。
- **依赖**：阶段 0。
- **任务**：
  - 前端：初始化 Next.js（静态导出）+ Tailwind；搭 9 个页面空壳 + 底部标签导航骨架。
  - 后端：Node.js（Fastify）服务 + `/health` + 三接口空桩；引入服务端 ffmpeg。
  - 数据库：Supabase 建表（profiles / practice_records / user_settings）+ 开启 RLS + 邮箱 Auth。
  - 部署：前端部署 Vercel、后端部署 Render/Railway，配好环境变量，前端可调到后端 `/health`。
- **阶段产出**：可访问的前端空壳 + 可调用的后端 + 可登录的 Supabase。
- **验收标准**：打开前端链接看到带底部导航的页面骨架；后端 `/health` 正常；用邮箱完成一次注册/登录。
- **设计依据**：[文档 3](03-UI-INTERACTION.md)（IA/页面结构）、[文档 4](04-ARCHITECTURE.md)（架构/模块）、[文档 5](05-DATABASE.md)（表设计）。

### 阶段 2 — 核心闭环（登录 → 选句 → 讲解 → 跟读 → 评分）【MVP 关键】

- **目标**：跑通产品核心价值闭环。
- **依赖**：阶段 1。
- **任务**：
  - 前端：登录页（邮箱登录/注册）、选句页（输入/查询/最近练习）、讲解页（讲解 + 语调标注 + 折叠语法分析）、跟读页（听示范/录音/评分展示）、记录页（最简只读列表，验证保存闭环）。
  - 后端：实现 `/api/explain`（DeepSeek 讲解）、`/api/assess`（ffmpeg 转码 + Azure 评估 + 语速计算）、`/api/tts`（Azure TTS）。
  - 数据库：评分结果写 `practice_records`（含 user_id / translation）。
  - AI 能力：接通 DeepSeek（最小调用验证 deepseek-flash 有效：一条西语句子返回结构化讲解，响应时间达标、中文讲解质量可用、JSON 契约稳定、关键字段缺失时降级/重试；质量不达标再试 deepseek-v4-pro）、Azure 发音评估（最小调用验证 es-ES 下实际返回：准确/流利/完整/总分 + 词级；并确认不返回 prosody 与音节级）、Azure TTS。
- **阶段产出**：可完成一次「登录 → 查一句 → 听 → 读 → 得分 → 记录保存 + 最简记录页可查」的完整流程。
- **验收标准**（用户视角）：① 注册登录后进选句页；② 输入 `¿Dónde está la biblioteca?` 点查询 → 看到翻译/核心记忆点/可展开语法 + 语调标注；③ 去跟读 → 听示范（可调语速）；④ 录音读一句 → 看到总分 + 三维 + 语速 + 逐词高亮 + 提升方向；⑤ 故意读错某词发音 → 该词标红、准确度分明显下降（验证 P1 的发音质量反馈）；⑥ 最简记录页能查到这次记录（证明保存闭环）；⑦ 用目标手机（含 iOS Safari）实录 → 不同浏览器录制格式（webm/opus、mp4/aac）均能上传并正确评估（验证格式探测 + 后端多格式转码）；⑧ 模拟「评分成功但保存失败」（断网/RLS 拒绝）→ 评分结果保留 + 提示 + 重试 → 恢复后最简记录页可查到。⑨ 模拟 `annotation` / `memoryTip` 缺失 → 讲解页不崩、其余内容正常、对应区块隐藏 + 提示「该部分未生成」（验证降级可用，区别于完整成功）。
- **设计依据**：[文档 2](02-FEATURE-SPEC.md)（F2/F3/F4）、[文档 3](03-UI-INTERACTION.md).4/3.5/3.6、[文档 6](06-API.md)（接口）。

### 阶段 3 — 周边功能（句子库 / 磨耳朵 / 记录 / 设置 / 文字识别）

- **目标**：补齐核心闭环之外的功能，形成完整 v1。
- **依赖**：阶段 2。
- **任务**：
  - 前端：句子库页（约 20–30 条入门静态句 + 难度/场景/语法点筛选器）、磨耳朵页（范围/语速/间隔/显示 + 循环播放）、记录页完善（日期分组/空态）+ 记录详情页、设置页（方言/分享/清除）、文字识别（Tesseract.js 接入选句页）。
  - 后端：无新增（磨耳朵复用 `/api/tts`）。
  - 数据库：沿用 `user_settings` 和现有 RLS；Task 4 为固定播放偏好与自定义选择增加已批准字段及迁移，不新增表。
- **阶段产出**：F1–F8 全部可用。
- **验收标准**（用户视角）：① 句子库能按难度/场景/语法点筛选，点句进讲解；v1 不提供「来源」筛选；② 磨耳朵能在已学/全部/自定义范围内播放去重句子，自定义从句库与本人已练句合集多选，零选中不能开始，播放偏好和选择重新登录后仍在；能调语速、选择 1/2/4 秒句间隔、开关原文/翻译，离开即停；③ 记录页/详情页能看到历次得分，能「再练一次 / 查看讲解」（再练一次：翻译不丢、无语调标注不报错）；④ 设置页能切方言、分享链接、清除记录；⑤ 拍照/相册能识别西语回填输入框（可编辑）。
- **磨耳朵默认与失效数据核对**：首次使用为全部 / 1.0× / 2 秒 / 仅显示原文；首次选自定义不全选；重复句只出现一次；练习记录清除或句库变化后，失效的自定义选择不计数、不播放。迁移后已有用户的方言保持不变，播放偏好得到默认值。
- **句库内容核对**：保持约 20–30 条入门句范围；以 PCIC 为教学依据、以本项目原创例句为主体；逐条检查 `source` 是否反映真实句子出处，不能把参照 PCIC 创作的句子误标为官方原句。
- **设计依据**：[文档 2](02-FEATURE-SPEC.md)（F1/F5/F6/F7/F8）、[文档 3](03-UI-INTERACTION.md)（各页结构/流程/数据流）。

### 阶段 4 — 已确认产品调整、可靠性打磨与分享上线（目标计划）

**目标与边界**：基于阶段 3 已部署产品，落实三组已确认决策：发音反馈与复练、个人句子与听熟、任务与评分恢复；再完成原定的移动端、PWA、错误状态、性能、安全、限流、用量和分享工作。本节是**待实施计划**，不表示新表、页面或恢复能力已经部署。必要的数据库 schema、迁移执行、部署变更及任何新依赖，均须按仓库规则另行审查和授权。

**执行顺序**：S4-0 → S4-1 → S4-2；S4-3 与 S4-4 在 S4-2 后可独立推进；S4-5 依赖 S4-1 至 S4-3；S4-6、S4-7 在核心链路稳定后收口；S4-8 先做分享前技术与安全验收，获用户批准分享后再做朋友真实试用的最终发布验收。个人开发可顺序完成，但不能跳过前置验证。每个任务完成时记录实际证据与尚未验证的设备或服务，不用自动化模拟冒充真人发音或 iPhone Safari 真机结果。

#### S4-0｜现状与技术设计核对（v1 前置）

- **目标**：把已确认的产品规则转成可实施且可验证的数据、状态和回退方案，同时保留未冻结的工程选择。
- **范围**：核对现有代码、生产实际 schema、仓库中的 `supabase/migrations/` 文件及目标环境的 migration 记录；确认是否存在 SQL Editor 手动执行但迁移历史未登记的差异。针对个人句子身份与历史评分归集、旧播放选择、固定评分记录 ID、短期快照和 RLS 形成最小技术设计与验证用例；其中同 ID 云端记录与待恢复快照内容不一致须列为冲突情形，不能只凭 ID 判定已保存。明确哪些检查能在隔离环境完成、哪些需要有范围限制的生产账号验证。
- **前置**：现行文档 1–6 与 Design System 已同步；只做只读核对，未获批准前不修复远端 migration 历史、不改 schema、不清测试数据。
- **验收**：有可核对的「仓库迁移文件 ↔ 实际 schema ↔ 远端迁移记录」差异清单和安全处置顺序；同句身份、用户隔离、旧数据降级、快照失效、重复保存及同 ID 内容冲突各有测试情形和预期结果；需用户批准的 schema/数据清理/部署或新增依赖事项单列，不把猜测当已部署事实。若历史不一致，先处理或明确阻断迁移执行，不能直接重放旧 SQL。

#### S4-1｜个人句子数据基础与迁移（v1 必要）

- **目标**：形成与练习记录独立、按用户隔离且能跨设备找回的个人句子集合，并为同句历史关联提供一致语义。
- **范围**：在获批物理设计及迁移方案后，新增必要的数据结构/权限和最小数据访问能力；保守句子身份同时用于个人句子去重、评分分组和移出后重新收录与旧评分的关联。自定义听熟选择使用稳定的个人句子标识；评分历史不得以该条目持续存在为读取前提。核对旧 `user_settings` 值及引用，保留旧评分记录的可读性。
- **前置**：S4-0 完成；远端 migration history 差异已安全处理或明确可控；执行任何生产迁移前取得对应批准和回退/验证安排。
- **验收**：同一用户重复成功讲解不产生重复个人句子；明显的空白、大小写或 Unicode 表示差异按技术设计确定的保守规则处理，重音符号、词语或可能变义的标点不被擅自合并；移出再收录仍能从记录页看到同句旧评分，且不产生跨用户关联。清除练习记录保留个人句子，移出个人句子保留评分历史。匿名及另一测试账号均不能读取、插入、修改或删除本账号个人句子、评分和设置。旧记录不自动补入个人集合；旧选择无法解析时不播放错误句子。迁移在隔离验证后才可安排生产执行，保留执行前后 schema/RLS 与应用路径的核对证据。

#### S4-2｜选句入口与讲解后收录（v1 必要）

- **目标**：让用户从自己遇到的句子开始学习，并在成功讲解后自然形成个人学习内容。
- **范围**：一级导航改为「选句／听熟／记录」；移除面向用户的系统句库页、系统句选择与「随机一句」，保留输入、粘贴、OCR、清楚的示例、首次引导和最近练习回填；最近练习从当前用户完整云端历史按稳定分页查找最多 5 个不同句子，使用统一身份规则去重。成功讲解后自动收录原句及可用译文。个人句子从听熟页入口进入独立管理页，支持重新学习与确认移出；收录失败保留讲解，只重试收录，不自动再请求 AI。
- **前置**：S4-1 的个人句子读写、身份规则和权限已可验证；沿用现有 `/api/explain` 与 OCR 能力。
- **验收**：全新账号不依赖预置句也能完成第一次查询；成功讲解后另一设备登录可找回该句；同句重复查询去重；模拟仅收录写入失败时讲解仍可读、明确显示未收录并能单独重试，AI 讲解调用次数不增加。移出后该句不再进入个人候选与听熟，但其评分仍可查；再次成功讲解可重新收录。OCR 回填仍可编辑。旧句库/随机入口不再出现在用户路径中。

#### S4-3｜评分反馈、记录详情与轻量复练（v1 必要）

- **目标**：使一次评分能直接指向改进动作，并让用户客观看清同一句近期总分变化；分数波动本身不用于断言学习能力持续进步。
- **范围**：评分页选中可靠对应的词后按需播放当前方言的 Azure 标准词音；保留整句示范，播放互斥，录音前停止示范，不预合成所有词。记录详情显示最近最多 5 次总分、固定 0–100 纵轴的简洁变化曲线；最近一次可靠已存反馈与简短复练目标优先，历史明细默认收起。记录详情「再练一次」直接显示薄弱词和目标；「查看讲解」保留为按需入口；评分页「再读一次」带着本次可用反馈继续，不把旧分数显示成新结果。
- **前置**：S4-1 的同句历史归集；S4-2 的新学习路径。词级可靠性判定与展示降级需在实施设计中核对现有评分数据，不新增 AI 或词级专项评分。
- **验收**：es-ES/es-MX 两档下词音与整句示范遵循同一方言设置；只有用户点击选中词才请求 TTS，加载、停止、失败重试可用。趋势 1 次为单点、2 次为两点、3 次及以上连线，最多 5 次且纵轴固定 0–100；无四指标切换，历史明细可按需展开。即时评分、记录详情和复练目标按同一反馈规则使用可靠词级数据以及准确度、流利度、完整度和可用语速；覆盖满分、维度偏低但无可靠弱词、反馈缺失/异常。新评分首次成功得到 100 分时，隐藏「下次留意」，在总分附近只触发一次短暂星光与微粒效果，不添加鼓励文案；恢复快照与查看历史不重播，遵守减少动态效果设置。记录详情反馈区有可见标题，日期与分数来自同一反馈记录；若展示的是较早的最近可靠反馈，应清楚标出其来源日期及分数。讲解收录中/成功/失败均有短暂 Toast；失败 Toast 消失后仍有明确未收录状态及可发现的只重试收录入口，重试不重新请求 AI。逐词对齐不可靠或反馈缺失时不虚构薄弱词，改用有根据的句级目标；复练无需自动调用 `/api/explain`，原讲解标注不为此新增云端字段。移出再收录后同句旧成绩仍在同一回顾链路。

#### S4-4｜听熟任务与个人句子库（v1 必要）

- **目标**：让用户轻松找到想听熟的本人句子，主动开始连续聆听，并能在整组播放中对单句进行精听。
- **范围**：听熟首页提供「全部」/「自定义」范围、句数、必要设置和开始操作，不平铺全部句子；管理模式与自定义选择模式进入共用的个人句子库能力。句子库按首次收录时间月→日分组，支持折叠、按西语原文/中文译文搜索；选择模式支持月/日/单句勾选和部分选中状态，搜索时仅逐条选择匹配句。草稿仅确认时持久化，取消/返回不保存。管理模式提供重新学习和移出，保留已有移出与评分历史规则。大列表稳定分页。连续任务与单句精听互斥；精听循环复用当前音频、可暂停/继续/切换/结束；结束恢复原组暂停上下文而不自动续播。可调精听语速时只为当前句重新生成一次。离页停止并释放音频；不新增中文 TTS 或云端播放服务。

#### S4-8｜整体验收与分享决策（v1 发布闸门）

- **目标**：分别确认技术与安全条件已达到可分享状态，以及获准分享后真实朋友能完成学习。
- **范围**：先执行 7.3 中无需邀请朋友的端到端矩阵、相关 typecheck/lint/build 与已有定向测试；按真实改动补充必要的身份、播放选择、评分保存/恢复、RLS 回归。核对生产部署与文档目标的差异，记录未测项和可接受限制。只有用户批准分享后，才邀请朋友完成真实注册、登录及一次学习，并据此完成发布验收。
- **前置**：技术与安全验收依赖 S4-1 至 S4-7 通过；朋友真实试用另依赖用户批准分享。任何测试数据清理均须另获按账号、按范围的明确授权。
- **验收与结论**：① 核心「自己的句子 → 讲透 → 读好 → 听熟 → 回顾 → 复练」在目标手机和桌面端走通；跨账号隔离、移出/清除语义、刷新和保存中断、旧设置降级均有证据；自动化检查通过且无未处理的阻断问题。此时只可记录为「技术与安全检查通过，等待用户批准分享」，并提交实际部署状态、调用/费用、风险和分享建议。② 用户明确批准分享后，由朋友通过分享链接真实注册、登录并完成一次学习；该证据通过且无发布阻断问题，才可记录「Stage 4 最终 PASS／分享上线完成」。未批准分享或尚未完成朋友试用时，不得把①记为最终 PASS；本计划不构成自动邀请或发布授权。

**后置，不作为本次 v1 上线门槛**：系统原创句库、随机一句、场景/分数筛选、「最近 N 句」范围、中文 TTS、复杂句子管理、词级专项录音评分、跨历史薄弱词聚合、真实音高曲线及完整讲解/录音的长期持久化。AI 查询偶发超时和讲解可信度的专项产品改造继续后置；若现有接口故障已阻断基本学习路径，则按通用稳定性故障处理，不借机扩大功能范围。

**实施前仍需收口的技术细节与授权**：个人句子的物理字段、唯一约束、保守身份算法、译文更新和移出方式；同句历史查询及反馈可靠性判定；短期快照介质、有效期、写入/清除时序与同 ID 保存核对；旧 migration history 的安全对齐方式。这些由 S4-0 提出最小技术方案，不在本计划中冻结。涉及实际数据库 schema/迁移、指定测试账号数据清理、新软件依赖、付费或部署变更时，按仓库规则另获批准。限流/用量告警阈值和可接受预算在对外分享前请用户确认；未获分享决定前不以本计划自动发布。

## 7.3 Stage 4 端到端验收矩阵

以下是阶段 4 的目标验收；阶段 2/3 当时的验收证据仍留在历史记录，不以旧句库、旧范围或「标红」验收新设计。每项记录测试账号、设备/浏览器、数据状态、请求与页面证据；真实录音和 iPhone Safari 系统交互只以本人真机操作为证据，自动化仅验证可自动化的路径。

1. **新用户首句**：注册/登录 → 看到输入示例和首次引导 → 输入/粘贴或 OCR 回填并编辑 → 查询成功 → 看到翻译、讲解与可用标注 → 自动收录个人句子。没有系统句库或随机一句入口；收录失败只重试写入、不重复讲解。
2. **个人句子与历史独立**：跨设备找回同一句；保守去重不合并有意义的差异；移出后听熟候选消失但历史仍可查；再次成功讲解重新收录并关联旧评分；清除评分不移出个人句子。现有旧记录可读，但不自动收录为个人句子；旧播放引用安全失效。清理测试数据另获授权。
3. **读好与复练**：真人录音得到总分、三维、语速及可信的词级反馈；选中词可按当前方言听标准发音，整句示范保留且与录音互斥。记录详情最多 5 次总分固定 0–100，1/2/3 次分别按单点/两点/连线显示；最近可靠反馈形成简短目标，缺失时合理降级；历史默认收起。「再练一次」直接带目标进入跟读，完整讲解按需查看，不自动请求 AI。
4. **听熟与个人句子库**：默认「全部」并显示有效句数；独立选择页按收录月→日分组，支持搜索、批量/单条选择、部分勾选、草稿取消和确认持久化；管理页共享分组/搜索而不显示选择控件。失效选择被过滤，自定义零有效句呈空态。进入、搜索、展开列表不请求 TTS；整组主动开始后按所选句播放。单句精听暂停整组、复用一次取得的音频循环，暂停/继续/切换/结束可用，结束恢复整组暂停上下文。语速、间隔、连续循环、离开停止和音频清理正确；中文译文不请求中文 TTS。
5. **任务与评分中断**：刷新、前后台切换、录音/评分请求中断及保存中断分别显示准确状态；不恢复录音、不自动重评/重讲解。已返回未保存评分尽可能恢复，先核对当前用户云端同 ID 与评分内容，再决定是否以原 ID 重试；响应丢失不产生重复记录。同 ID 内容冲突时不误判已保存、不静默覆盖或丢弃快照。网络暂时不可用保留有效快照，换账号与无权访问不能泄露任务；Stage 2 的返回保护和保存失败重试继续有效。
6. **移动与 PWA**：目标 iPhone Safari 的产品路径真人录音、示范、OCR、回顾与听熟可用；桌面端同一学习任务无功能缺口。长句、键盘、安全区域、文字放大与触控位置可用；可加主屏并从图标打开。权限、断网、AI/TTS 失败及空态有清楚恢复路径；离线不伪装为在线 AI 可用。
7. **数据安全与运营**：匿名和账号 B 不能访问账号 A 的个人句子、设置与评分；限流、请求约束、CORS 与用量告警在目标环境有核对证据。用户可查看实际调用与费用边界；分享链接不泄露个人数据。上述技术与安全检查通过后仅进入「等待用户批准分享」状态；获准后朋友真实注册、登录并完成一次学习，才构成 Stage 4 最终发布验收。

适用的仓库检查至少包括 `npm run typecheck`、`npm run lint`、`npm run build`、`npm run test -w api` 及受影响的现有前端定向测试；仅运行项目实际提供的命令，并按实现变化增补必要回归。对 AI、录音、RLS 和 PWA 的真实能力仍须设备/服务验证，不能只凭编译或模拟结果宣布通过。
