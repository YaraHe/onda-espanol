# 文档 4 · 系统架构设计

> 从产品与技术结合的视角，说明系统由什么组成、为什么这样设计、各模块如何协作。不含具体代码、API 定义、表结构或底层算法实现。
> 本文档描述已确认的 Stage 4 目标架构。S4-1 个人句子物理设计已记录于[文档 5](05-DATABASE.md)并在隔离测试项目验证；尚未部署到 Production。短期任务恢复仍待实施。

## 4.1 整体架构设计

### 4.1.1 分层架构

系统分为四层，前后端分离：

```
┌─ 客户端层（浏览器 · Next.js 静态托管于 Vercel CDN）──────────┐
│  UI + 短期任务快照 + 录音(MediaRecorder) + OCR(Tesseract.js) + Supabase │
└──────────────┬──────────────────────────────────┘
               │ HTTPS（不传密钥）
┌──────────────▼──────────────────────────────────┐
│ 服务层（独立 Backend Service · Node.js 常驻进程）  │
│  /api/explain · /api/assess · /api/tts           │
│  职责：音频转码(ffmpeg)、AI 调用编排、密钥托管、响应适配 │
│  部署：Render / Railway                           │
└──────────────┬──────────────────────────────────┘
               │ HTTPS（服务端密钥鉴权）
┌──────────────▼──────────────────────────────────┐
│ AI 能力层（第三方）                                │
│  DeepSeek（语法讲解，国内 LLM）                    │
│  Azure Speech（发音评估 + 神经语音合成）            │
└──────────────────────────────────────────────────┘
（数据层：Supabase Postgres + Auth（个人句子/练习记录/设置/账号）；音频不持久化）
```

### 4.1.2 设计思路与核心目标

- **核心目标**：围绕用户自己遇到的一句话提供「讲透（语法）+ 读好（发音）+ 听熟」的闭环，不提供系统化预置句子课程。
- **设计原则**：
  1. **前后端分离**：前端静态托管在 CDN，后端独立常驻服务，各自独立部署、独立扩容。
  2. **密钥不下发**：AI 服务密钥只存后端服务，前端通过自有 API 间接调用。
  3. **AI 能力解耦**：语法讲解（DeepSeek）、发音评估（Azure）、语音合成（Azure）、文字识别（本地 OCR）各自独立，可单独替换或降级。
  4. **重处理放后端**：音频转码、格式适配等重活由后端承担，前端保持轻量，移动端更稳。
  5. **移动优先 + 成本可控**：手机浏览器为主，支持添加到主屏；AI 服务按量付费，个人量级月成本几十元。

### 4.1.3 核心模块构成

| 层 | 模块 | 职责 |
|---|---|---|
| 客户端 | UI 层 | 选句/听熟/记录三个一级入口及其学习页面的渲染与交互 |
| 客户端 | 录音模块 | 采集麦克风音频（webm/opus 优先，回退 mp4/aac） |
| 客户端 | OCR 模块 | 本地识别图片中的西语文字 |
| 客户端 | 数据访问模块 | 个人句子、练习记录、设置的云端读写（Supabase） |
| 客户端 | 短期任务快照 | 在当前标签页内尽可能恢复跟读上下文及未保存评分；不存录音 |
| 服务端 | explain 路由 | 编排 LLM 语法讲解 |
| 服务端 | assess 路由 | 音频转码 + 发音评估 + 语速计算 |
| 服务端 | tts 路由 | 编排语音合成 |
| 服务端 | 音频转码模块 | ffmpeg 将录音（webm/opus 或 mp4/aac）统一转 wav/16kHz |
| AI 能力 | 语法讲解（DeepSeek） | 产出结构化讲解 + 语调标注 |
| AI 能力 | 发音评估（Azure） | 产出三维分 + 逐词反馈 |
| AI 能力 | 语音合成（Azure TTS） | 产出西语整句、选中词示范及听熟音频 |

### 4.1.4 模块协作关系

- UI 层是所有能力的入口与出口：发起请求、接收结果、渲染。
- 录音模块（浏览器）→ assess 路由（后端）→ 音频转码模块（ffmpeg）→ Azure 发音评估 → 评分结果 → UI。
- OCR 模块在浏览器本地运行，不经过后端；数据访问模块经 Supabase SDK 直接读写云端。
- 三个后端路由是 AI 能力层的唯一调用方，负责密钥托管、参数组装、返回适配。

### 4.1.5 全链路核心数据流（学习一句）

```
选句页输入/OCR/找回句子 → explain 路由 → DeepSeek 讲解（含语调标注）→ 讲解页展示
→ 讲解成功后按用户去重收录个人句子（收录失败可单独重试）
→ 去跟读 → 录音(webm/opus 或 mp4/aac) → assess 路由 → ffmpeg 转码 wav/16kHz → Azure 发音评估
→ 三维分 + 逐词反馈 + 语速 → 跟读页评分展示与短期待保存快照 → 结果写 Supabase（练习记录）
→ 最近反馈/词与整句示范/轻量复练；个人句子进入听熟播放候选
```

## 4.2 技术选型

### 4.2.1 前端

| 维度 | 选型 | 核心依据 | 适用场景 |
|---|---|---|---|
| 框架 | Next.js（静态导出）+ TypeScript | 技术栈熟悉、静态托管到 CDN、无 Serverless 依赖 | 移动优先 Web App |
| 样式 | Tailwind CSS | 快速实现响应式移动端 UI | 同一学习路径适配手机与桌面 |
| 录音 | MediaRecorder（webm/opus 优先，回退 mp4/aac） | 浏览器原生、压缩体积小、上传轻 | 口语评估音频采集 |
| OCR | Tesseract.js（`spa` 语言包） | 免费、纯浏览器本地运行 | 文字识别填句 |

> 注：原「ffmpeg.wasm 前端转码」改为后端 ffmpeg，前端不再加载重型 wasm。
> 注：录音格式按浏览器能力探测——Chrome/Firefox/Edge 原生支持 webm/opus；Safari 18.4 起才支持 webm/opus（更早版本仅 mp4/aac）。客户端用 `MediaRecorder.isTypeSupported()` 探测后上传实际 MIME，后端统一转码；仅当浏览器不返回任何受支持的录制格式时才提示浏览器不支持。

### 4.2.2 后端

| 维度 | 选型 | 核心依据 | 适用场景 |
|---|---|---|---|
| 框架 | Node.js（Fastify） | 与前端同为 TS 技术栈、适合音频流处理、生态成熟 | 常驻 API 服务 |
| 音频转码 | 服务端 ffmpeg | 稳定、支持 webm/opus 与 mp4/aac → wav/16kHz、释放前端压力 | 评估前音频预处理 |
| 部署 | Render / Railway（容器） | 免运维、HTTPS、常驻进程、低价档 | 个人生产量级后端 |

### 4.2.3 数据存储

| 维度 | 选型 | 核心依据 | 适用场景 |
|---|---|---|---|
| 云端数据 | Supabase（Postgres + Auth） | 多用户、云端持久化、可换设备同步、RLS 权限隔离 | 个人句子、练习记录、设置、用户资料 |
| 短期恢复 | 当前标签页内的最小任务快照 | 刷新后继续任务并尽可能保留未保存评分 | 原句、译文、可用提示、复练目标与待保存结果；不存录音 |

### 4.2.4 AI 能力

| 能力 | 选型 | 核心依据 | 适用场景 |
|---|---|---|---|
| 语法讲解（LLM） | DeepSeek（deepseek-flash） | 国内直连、成本最低、中文强、OpenAI 兼容 API | 语法讲解 + 语调标注 |
| 发音评估（ASR+评测） | Azure Speech 发音评估 | 支持西语发音评估（准确/流利/完整/总分 + 词级）；韵律分与音节级仅 en-US，西语不返回；重音/语调由 LLM 讲解 + TTS 示范承载 | 口语三维评分 |
| 语音合成（TTS） | Azure Neural TTS | 西语示范、支持 es-ES/es-MX、可调速 | 整句/选中词示范、听熟 |
| 文字识别（OCR） | Tesseract.js（本地） | 免费、离线、无需密钥 | 截图/拍照识字 |

## 4.3 模块设计

### 4.3.1 客户端 · UI 层

- **负责**：三个一级入口及从属学习页面的渲染、交互、状态流转（见[文档 3](03-UI-INTERACTION.md)）。
- **输入**：用户操作（输入/点击/录音/拍照）、后端返回的结果。
- **输出**：页面展示，以及对后端 API/本地模块的调用。
- **跨模块**：调用后端 3 个 AI API；调用录音/OCR/短期快照及 Supabase 数据访问模块；不直接接触第三方 AI 服务。

### 4.3.2 客户端 · 录音模块

- **负责**：麦克风音频采集。
- **输入**：用户朗读。
- **输出**：音频（webm/opus 优先，回退 mp4/aac，压缩体积小）。
- **跨模块**：被 UI 层调用；输出上传给 assess 路由；不做本地转码。

### 4.3.3 客户端 · OCR 模块

- **负责**：图片中的西语文字识别。
- **输入**：拍照/相册图片。
- **输出**：识别出的西语文本（回填输入框，可编辑）。
- **跨模块**：被 UI 层调用；Tesseract.js 本地运行，不经过后端、不涉及密钥。

### 4.3.4 客户端 · 数据访问模块

- **负责**：个人句子、练习记录和设置的云端读写。
- **输入**：成功讲解后的句子/译文、评分结果、用户设置。
- **输出**：个人句子列表、练习记录和设置（供选句/听熟/记录/设置读取）。
- **跨模块**：被 UI 层调用；经 Supabase SDK 直接读写云端数据，受 RLS 权限约束，需登录态。

### 4.3.4a 客户端 · 短期任务快照

- **负责**：当前标签页刷新后恢复原句、译文、已有必要提示、复练目标及已返回但待保存的评分；云端个人句子与记录提供已保存内容的找回。
- **边界**：只存最小必要文字和结果，不存录音；绑定当前用户并设失效条件。录音与评估中的请求不能续传，不自动重发 AI/评分请求。本地快照不表示云端已保存；具体存储介质、时效和写入时序由实施设计确定。

### 4.3.5 服务端 · explain 路由

- **负责**：语法讲解的调用编排。
- **输入**：`sentence`、`lang`。
- **输出**：结构化讲解（翻译/时态/动词变位/语序/语调标注/记忆点/对比）。
- **跨模块**：被 UI 层调用；依赖 DeepSeek；负责隐藏密钥、组装 prompt、约束结构化输出、校验关键字段（缺失时重试一次）、适配错误码。

### 4.3.6 服务端 · assess 路由

- **负责**：音频转码编排 + 发音评估 + 语速计算。
- **输入**：音频（webm/opus 或 mp4/aac）、参考文本 `sentence`、`lang`。
- **输出**：总分 + 三维分 + 语速 + 逐词反馈。
- **跨模块**：被 UI 层调用；依赖音频转码模块与 Azure 发音评估；从词级时间戳算 wpm，再统一成前端所需结构。

### 4.3.7 服务端 · tts 路由

- **负责**：语音合成的调用编排。
- **输入**：`sentence`、`lang`、`rate`（可选语速）。
- **输出**：音频流。
- **跨模块**：被 UI 层调用（整句/选中词示范、听熟）；依赖 Azure TTS；中文翻译只在屏幕显示，不调用中文 TTS。

### 4.3.8 服务端 · 音频转码模块

- **负责**：把浏览器录音转成评估所需格式。
- **输入**：webm/opus 或 mp4/aac 音频。
- **输出**：wav/16kHz/单声道音频。
- **跨模块**：被 assess 路由调用；基于 ffmpeg，服务端执行。

### 4.3.9 AI 能力模块（语法讲解 / 发音评估 / 语音合成）

- **语法讲解（DeepSeek）**：输入西语句子 → 输出结构化讲解；选句页点「查询」或用户主动点「查看讲解」时调用。个人句子浏览、直接复练与刷新恢复不自动请求 AI。
- **发音评估（Azure）**：输入音频 + 参考文本 → 输出逐词分数；仅在录音结束提交时调用，一次一次评估；返回需适配成前端展示结构（含语速）。
- **语音合成（Azure TTS）**：输入西语整句或选中词 + 方言 + 语速 → 输出音频；示范按需调用，听熟由用户主动开始后逐句调用；返回音频流直接播放。

## 4.4 核心业务流程

### 4.4.1 学习一句（选句 → 讲解 → 跟读 → 评分）

1. **用户输入**：选句页输入/粘贴/OCR 或找回本人句子得到 `sentence`，点「查询」。
2. **讲解调用**：UI → explain 路由 → DeepSeek。调用时机 = 点查询；频次 = 一句一次；依赖参数 = `sentence` + `lang`；返回适配 = 结构化结果映射为讲解页区块。
3. **讲解与收录**：讲解页展示翻译/核心记忆点，语法分析折叠；成功讲解后按当前用户保守去重收录个人句子。收录失败时保留讲解、提示并单独重试保存，不重复调用 AI。点「去跟读」沿用 `sentence` + `translation` + 已有 `annotation`。
4. **录音与评估**：录音(webm/opus 或 mp4/aac，按浏览器探测) → 上传 assess 路由（带实际 MIME）→ 后端 ffmpeg 转码 wav/16kHz → Azure 发音评估。调用时机 = 点停止；频次 = 每次录音一次；依赖参数 = 音频 + 参考文本 + 语言码；返回适配 = 三维分直出、语速由词级时间戳计算、逐词反馈映射到句子高亮。
5. **结果与写回**：跟读页展示总分/三维/语速/逐词反馈/提升方向，选中可靠对应的词可按需听标准发音。结果到达后尽可能先保留固定记录 ID 和待保存结果，再写入 Supabase；保存中断后按当前用户核对同 ID 记录的评分内容，一致才确认已保存，确未保存才以同一 ID 重试；内容冲突时不静默覆盖。记录详情在当前用户范围内按与个人句子去重一致的保守句子身份归集历史，移出和重新收录均不切断旧评分；取最近可靠反馈形成简短复练目标，并显示最近最多 5 次总分变化，完整历史默认收起。具体关联与防冲突实现待技术设计。
6. **异常兜底**：讲解失败 → 停留选句页可重试；可选字段缺省 → 隐藏对应内容并提示；录音/评估中刷新 → 恢复任务但提示重录，不保存音频或重发请求；保存失败 → 保留结果与返回保护，提示重试；网络暂时失败不清除仍可用的快照。

### 4.4.2 听熟

1. 一级导航进入听熟页 → 读取当前用户的个人句子及播放偏好。首次或范围值无效时用「全部个人句子」，有效已存自定义范围优先恢复；自定义选择按稳定个人句子标识过滤失效项，空选择保持空态。显示句数，具体句子列表默认收起。旧 `learned` 与旧句库/练习记录引用安全降级，不自动导入预置句。
2. 用户主动点播放 → 逐句调用 tts 路由 → Azure TTS 返回西语音频 → 循环播放。屏幕可显示/隐藏原文与中文翻译，中文不作语音播放。
3. 离开页面即停止播放并释放音频。
4. 异常兜底：无网络/单句失败 → 提示并停止。
5. 范围、语速、间隔、显示开关及自定义选择按用户云端保存；移出个人句子后失效选择不进入播放列表，音频不持久化。不新增服务端播放接口。扩大分享前落实限流与用量告警。

### 4.4.3 文字识别

1. 选句页点「文字识别」→ 调起拍照/相册 → Tesseract.js 本地识别。
2. 识别中入口按钮 loading；成功回填输入框（可编辑）；失败红字提示手动输入。
3. 全程本地，无网络、无密钥、无后端参与。

## 4.5 数据设计

| 数据类型 | 数据来源 | 存储位置 | 生命周期 |
|---|---|---|---|
| 用户身份 `user_id` / `email` | Supabase Auth | Supabase（auth.users） | 账号生命周期 |
| 用户资料 `nickname` | 用户输入（注册） | Supabase（profiles） | 长期 |
| 当前句子 `sentence` | 输入/OCR/个人句子找回 | 当前任务快照；成功讲解后进入个人句子集合 | 快照短期；个人集合按用户长期保留，可移出 |
| 个人句子 | 成功讲解 | Supabase（按用户隔离） | 可跨设备找回；移出不删除评分历史 |
| 讲解结果 `explanation` | DeepSeek | 当前学习会话 | 不作为云端讲解缓存 |
| 语调标注 `annotation` | DeepSeek（随讲解） | 当前任务可用时随短期快照恢复 | 不新增云端字段；复练缺省时不自动重取 |
| 评分结果 `result` | Azure 发音评估 | 待保存时短期快照；保存后 Supabase 练习记录 | 可恢复待保存结果；历史长期保留、可清除 |
| 练习记录 `records` | 评分结果累积 | Supabase | 长期保留，可清除 |
| 设置 `lang` 与听熟播放偏好 | 用户选择 | Supabase（`user_settings`） | 按用户长期保留；失效的自定义选择不参与播放 |
| 音频（示范/录音） | TTS / 麦克风 | 会话内（后端处理后即弃） | 不持久化 |

## 4.6 部署架构

### 4.6.1 前端部署

- Next.js 静态导出，部署到 Vercel CDN（自动 HTTPS、全球加速、静态缓存）。
- 移动端浏览器访问，可「添加到主屏」作为类 App 使用。

### 4.6.2 后端部署

- Node.js（Fastify）容器化，部署到 Render / Railway：常驻进程、HTTPS、可横向扩容。
- 三个 API 路由（explain / assess / tts）+ 服务端 ffmpeg 转码能力随容器部署。

### 4.6.3 AI 服务调用方式

- 全部由后端服务发起 HTTPS 调用；密钥存后端环境变量（`DEEPSEEK_API_KEY`、`AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION`），仅后端读取，绝不下发浏览器。
- OCR 例外：Tesseract.js 在浏览器本地运行，无密钥、无网络调用。

### 4.6.4 第三方服务依赖

| 服务 | 用途 | 依赖程度 |
|---|---|---|
| DeepSeek | 语法讲解 + 语调标注 | 核心（讲解功能必需） |
| Azure Speech（发音评估 + TTS） | 口语评分 + 示范/听熟音频 | 核心（评估、音频必需） |
| Supabase | 数据存储 + 账号登录 | 核心（个人句子、练习记录、设置必需） |
| Tesseract.js | 文字识别 | 增强（可降级为手动输入） |
